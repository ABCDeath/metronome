## Component Specifications

### Beat Grid

**Location:** New `<div class="section">` block inserted between the Subdivision section and the Accent section in `App.svelte`. Heading: "Pattern".

**Structure:**
```
<div class="section">
  <h2>Pattern</h2>
  <div class="beat-grid" role="group" aria-label="Beat pattern">
    <!-- N buttons, one per step -->
    <button class="beat-cell {voiceClass}" type="button" onclick={...}>
      {label}
    </button>
  </div>
</div>
```

**Grid layout:** `display: flex; flex-wrap: nowrap; gap: 4px; overflow-x: auto;`
- Cells never wrap to a second row — the grid scrolls horizontally at high step counts.
- Each cell: `flex-shrink: 0; min-width: 44px; min-height: 44px; width: calc((100% - (N-1)*4px) / N)` where N = step count; clamped to min 36px via `max(36px, ...)` — at N > 12 cells will be narrower than 44px; horizontal scroll kicks in at that point.

**Cell interaction:**
- Single click (or tap) cycles voice: Normal (0) → Accent (1) → Silent (2) → Normal (0).
- No long-press, no right-click menu, no drag.
- Change takes effect on the next beat event (not mid-beat). The `$effect` that calls `engine.updatePattern(pattern)` fires immediately on voice mutation; the scheduler picks it up on the next `_schedulerTick`.

**Cell labels:**

| Voice | Label |
|-------|-------|
| 0 — Normal | N |
| 1 — Accent | A |
| 2 — Silent | — |

Labels are single characters or a single em dash. Font size 14px, weight 600. Labels are centered horizontally and vertically in the cell.

**CSS class names:** `.beat-cell` (base), `.beat-cell-normal` (voice 0), `.beat-cell-accent` (voice 1), `.beat-cell-silent` (voice 2).

**Accessibility:** `role="group"` on the container with `aria-label="Beat pattern"`. Each button has `aria-label="Beat {i+1}: {state}"` where state is "Normal", "Accent", or "Silent". Example: `aria-label="Beat 1: Accent"`. This allows screen readers and automated tests to identify cell state without visual inspection.

**Dynamic update:** When step count changes (subdivision or time-sig change), the grid re-renders with the new step count. Preserved assignments appear at their original positions; new positions show Normal. No animation — immediate DOM update.

### White Noise Slider

**Location:** New `<div class="section">` block appended after the Accent section. Heading: "Noise".

**Structure:**
```
<div class="section">
  <h2>Noise</h2>
  <div class="row">
    <input type="range" class="noise-slider" min="0" max="100" step="1" value={noiseLevel} oninput={onNoiseInput} />
    <span class="noise-value">{noiseLevel}%</span>
  </div>
</div>
```

**Behavior:**
- Range: 0–100 (integer percent). Maps to `noise_gain = noiseLevel / 100.0` before encoding as `Math.round(noiseGain * 1000)` for `Atomics.store(paramBuffer, 4, ...)`.
- Slider move is immediate — the `$effect` or direct `Atomics.store` on `oninput` writes slot 4. The worklet picks it up on the next `process()` frame (~2.9ms).
- Default value: 0 (no noise on first load). The user opts in explicitly.
- The readout shows the integer percentage: "0%", "5%", "100%". No decimal places.

**CSS:** `.noise-slider { flex-grow: 1 }` — matches `.bpm-slider` width behaviour. `.noise-value { width: 36px; font-size: 14px; text-align: right }` — matches `.amp-value`.

**No separate enable/disable toggle.** 0% on the slider is the off state. A toggle would add UI complexity for no functional gain (the PRNG runs regardless per D-12; the slider controls the mix coefficient only).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Beat grid section heading | Pattern |
| White noise section heading | Noise |
| Beat cell label — Normal | N |
| Beat cell label — Accent | A |
| Beat cell label — Silent | — (em dash, U+2014) |
| Beat cell aria-label template | Beat {N}: {State} (e.g., "Beat 1: Accent") |
| Noise slider value readout | {integer}% (e.g., "0%", "5%", "100%") |
| Empty state | Not applicable — grid always contains at least 1 beat |
| Error state | Not applicable — no server calls, no async failures in this phase |
| Destructive confirmation | Not applicable — no destructive actions in this phase |

**Rationale for single-character beat labels:** At 16 steps (4/4 + sixteenth subdivision) the grid must fit 16 cells in 480px with 4px gaps = ~26px per cell. Single characters ("N", "A", "—") are legible at 14px bold in a 26px cell. Full words ("Normal", "Accent", "Silent") would overflow.

## Interaction States

### Play/Stop button — no change from Phase 3

No modification to the Play/Stop button or its states.

### Beat grid cell — state machine

```
Normal ──click──→ Accent ──click──→ Silent ──click──→ Normal
  (voice=0)          (voice=1)          (voice=2)
```

- Active/pressed state (`:active`): background transitions to the next state's color for visual feedback. Example: Normal cell pressed → briefly shows #333 background (Accent color) before the click handler fires and the state actually updates.
- No keyboard-triggered cycle; keyboard tab-focus is supported (buttons are natively focusable), but Enter/Space triggers the native button click which fires the same cycle handler.

### Noise slider — continuous

- Slider thumb moves freely from 0 to 100.
- The percentage readout updates on every `input` event (not just `change`).
- No discrete steps shown visually; `step="1"` prevents fractional values but the slider renders as a continuous track.

## Layout Integration

The Phase 4 additions slot into the existing `.controls-container` column layout:

```
<main> (flex column, align-items center)
  <h1>Metronome</h1>
  <button id="play-btn">Play / Stop</button>
  <p class="status">Status: …</p>
  <div class="controls-container"> (max-width 480px)
    [BPM section]          ← existing
    [Time section]         ← existing
    [Subdivision section]  ← existing
    [Pattern section]      ← NEW (Phase 4)
    [Accent section]       ← existing (renamed heading from "Accent" → no rename; keep "Accent")
    [Noise section]        ← NEW (Phase 4)
  </div>
</main>
```

No layout changes to existing sections. The Pattern section appears between Subdivision and Accent because conceptually the user sets the time structure (BPM → Time → Subdivision) then customises the pattern, then tunes the accent sound.
