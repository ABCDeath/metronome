# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Timing Controls.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — native HTML elements only |
| Icon library | none — text labels on all buttons |
| Font | system-ui, sans-serif (existing; src/App.svelte) |

**Rationale:** No shadcn or Tailwind is present. The project is Svelte 5 + Vite; shadcn targets React. The existing App.svelte uses inline `<style>` blocks with system fonts and neutral grays. Phase 3 extends this pattern with the same approach — no new design system introduced.

---

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between step buttons (−5 −1 +1 +5), icon-to-label gap |
| sm | 8px | Gap between label and input within a control group |
| md | 16px | Gap between control groups within a section (BPM row elements) |
| lg | 24px | Gap between major sections (BPM section → Time Signature section → Subdivision → Accent) |
| xl | 32px | Top/bottom padding inside the main panel |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Play/Stop button padding: `8px 32px` with `min-height: 44px` — meets touch target without a non-multiple-of-4 vertical padding value.
- Step buttons (−5, −1, +1, +5): padding `8px 16px` with `min-height: 44px`. The explicit min-height enforces the 44px touch target on Android without requiring a non-grid padding value.
- BPM number input width: fixed 64px to accommodate three digits plus padding.
- Time signature denominator select width: fixed 72px (four short options: 2, 4, 8, 16).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 32px (2rem) | 600 (semibold) | 1.2 | App heading "Metronome" — existing, carry forward |
| Heading | 20px (1.25rem) | 600 (semibold) | 1.3 | Section labels: "BPM", "Time Signature", "Subdivision", "Accent" |
| Body | 16px (1rem) | 400 (regular) | 1.5 | Step button labels (−5, −1, +1, +5), select options, input values |
| Label | 14px (0.875rem) | 400 (regular) | 1.4 | Secondary labels: "accent pitch", "accent amplitude", status text |

**Source:** Display size from existing App.svelte h1 (2rem). Button size from existing #play-btn (1.25rem) repurposed as section heading. Body and Label are defaults derived from browser legibility standards at the declared font stack.

**Weight constraint:** Exactly two weights declared for Phase 3 — 400 (regular) for body/label content, 600 (semibold) for display/heading content. No new Phase 3 elements introduce weight 700. Note: the existing h1 element ("Metronome") inherited from Phase 1/2 may render with a browser-default bold (700) via the UA stylesheet; this is a carry-forward browser default outside Phase 3's scope and does not constitute a Phase 3 weight declaration. All new elements introduced in Phase 3 use 600 or 400 exclusively.

Secondary text color: `#666666` — used for status text and secondary labels only. Not part of the 60/30/10 surface split.

## Component Inventory

Each component is described with exact HTML elements and interaction behavior. No third-party components.

### BPM Section

**Layout:** Single horizontal row. Left to right: section label "BPM" → range slider → number input → step buttons group.

**BPM Range Slider**
- Element: `<input type="range">`
- Min: 20, Max: 300, Step: 1
- Width: fills available space between label and number input (flex-grow: 1)
- Thumb: 20px × 20px circle, color `#333333`
- Track height: 4px
- Real-time: fires on `input` event, updates `pattern.bpm`, no debounce
- Source: D-01

**BPM Number Input**
- Element: `<input type="number">` or `<input type="text">`
- Width: 64px fixed
- Font size: 16px (Body)
- Text alignment: center
- Validates on `blur` and `Enter` keypress: clamp to [20, 300], reject non-numeric (revert to previous valid value on rejection)
- Two-way sync: slider change updates this input; this input change updates slider
- Source: D-01

**BPM Step Buttons**
- Four `<button>` elements in a row: labels "−5", "−1", "+1", "+5"
- Minimum touch target: 44px × 44px — enforced via `min-height: 44px`
- Padding: `8px 16px`
- Font size: 16px (Body)
- Border: 2px solid `#333`
- Background resting: `#f0f0f0` (Secondary)
- Background hover: `#e0e0e0` (4% darker than Secondary)
- Background active/pressed: `#333` with text `#fff`
- Border-radius: 6px
- Behavior: each click calls `adjustBpm(delta)` which clamps result to [20, 300]
- Keyboard: `Enter` and `Space` activate
- Note: these are specifically "really useful" to the user — must be visually prominent, not smaller than the Play/Stop button
- Source: D-01, CONTEXT.md specifics section

**BPM Step Buttons group spacing:** 4px gap (xs) between each button.

### Time Signature Section

**Layout:** Single horizontal row. Left to right: section label "Time" → numerator input → "/" separator → denominator select.

**Numerator Input**
- Element: `<input type="number">`
- Min: 1, Max: 12, Step: 1
- Width: 52px fixed
- Font size: 16px (Body)
- Text alignment: center
- Validates on `blur` and `Enter`: clamp to [1, 12], reject non-numeric
- Change triggers `onTimeSigChange()` which rebuilds the beats array
- Source: CONTEXT.md Claude's Discretion

**Denominator Select**
- Element: `<select>`
- Options: 2, 4, 8, 16
- Width: 72px fixed
- Font size: 16px (Body)
- Change triggers `onTimeSigChange()` which rebuilds the beats array
- Source: CONTEXT.md Claude's Discretion

**Separator**
- Plain text "/" between numerator and denominator
- Font size: 16px (Body), color `#333`
- Margin: 8px on each side (sm)

---

### Subdivision Picker

**Layout:** Single horizontal row. Section label "Subdivision" → four radio buttons displayed as a button group (pill row).

**Implementation:** Four `<input type="radio">` elements styled as a segmented button row. Labels: "Quarter", "8th", "Triplet", "16th".

- Selected state: background `#333`, text `#fff`, border `#333`
- Unselected state: background `#fff`, text `#333`, border `#333`
- Hover (unselected): background `#f0f0f0`
- Border-radius on group: 6px (left buttons have left-radius only, right buttons have right-radius only, forming a pill)
- Font size: 16px (Body)
- Minimum touch target: 44px height — enforced via `min-height: 44px`
- Padding: `8px 16px` per option
- Change triggers `onTimeSigChange()` with updated subdivision
- Source: CONTEXT.md Claude's Discretion (radio vs select choice made here: button group is more scannable than a select for four options)

### Accent Panel

**Decision (Claude's Discretion):** Always visible — not collapsible. Rationale: the accent settings are two simple controls (one toggle + one slider with toggle). Collapsing them saves only ~60px of vertical space while hiding functionality that musicians will adjust regularly. A collapsible panel adds interaction cost on every session.

**Layout:** Vertical stack. Section label "Accent" → two rows, one per accent parameter.

**Row 1 — Accent Pitch**
- Layout: `<label>` "Pitch (1400 Hz)" → `<input type="checkbox">` styled as toggle
- Toggle on (default): accent uses 1400 Hz. Toggle off: accent uses 1000 Hz (same as normal click).
- Toggle visual: pill-shaped checkbox, 36px × 20px. On state: `#333` fill. Off state: `#ccc` fill.
- Label font size: 14px (Label)
- Default: checked (on)
- Source: D-02

**Row 2 — Accent Amplitude**
- Layout: `<label>` "Amplitude" → `<input type="range">` slider → value display (e.g. "1.3×") → `<input type="checkbox">` styled as toggle
- Slider: min 1.0, max 1.5, step 0.1. Width: 120px.
- Value display: 14px (Label), shows current multiplier with "×" suffix, width 36px fixed (right-aligned)
- Toggle on (default): accent uses the slider value. Toggle off: accent amplitude = 1.0× (same as normal).
- Toggle visual: same pill-shaped style as Row 1 toggle
- Slider is disabled (grayed, pointer-events: none) when toggle is off
- Default: slider at 1.3, toggle checked (on)
- Source: D-03

**Accent panel spacing:**
- 8px (sm) between label and control
- 16px (md) between Row 1 and Row 2

## Layout

**Overall structure:** Centered vertical stack (`flex-direction: column; align-items: center`) inside `<main>`, full viewport height (`min-height: 100vh`). Gap between sections: 24px (lg).

**Primary visual anchor:** Play/Stop button — highest interaction frequency, visually dominant over timing control rows. It appears directly below the app heading and above all parameter sections to establish visual hierarchy and reinforce the start/stop action as the primary affordance.

**Section order (top to bottom):**
1. App heading: "Metronome" (Display, existing)
2. Play/Stop button (existing)
3. BPM section
4. Time Signature section
5. Subdivision section
6. Accent section

**Max width:** 480px. Panel is centered. This constrains the BPM slider to a usable length on desktop without stretching across wide screens.

**Responsive note:** On mobile (≤480px), the layout fills the full viewport width with 16px (md) horizontal padding. Step buttons maintain 44px minimum touch target. All control rows wrap if needed (flex-wrap: wrap).

**Status text:** "Status: stopped / running" — existing `.status` paragraph, remains below Play/Stop button (between Play/Stop and BPM section).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (play) | "Play" |
| Primary CTA (stop) | "Stop" |
| BPM section label | "BPM" |
| BPM step button labels | "−5" "−1" "+1" "+5" |
| Time signature section label | "Time" |
| Time signature separator | "/" |
| Subdivision section label | "Subdivision" |
| Subdivision options | "Quarter" "8th" "Triplet" "16th" |
| Accent section label | "Accent" |
| Accent pitch row label | "Pitch (1400 Hz)" |
| Accent amplitude row label | "Amplitude" |
| Accent amplitude value display | "{value}×" (e.g. "1.3×") |
| BPM validation error | Inline: revert to previous valid value; no error message shown. Silent clamp for slider/buttons; no toast needed. |
| BPM out-of-range (number input) | Border turns `#cc0000` for 500ms, then reverts to previous valid value. No separate error text. |
| Empty state | Not applicable — controls are always visible; no data-dependent empty state |
| Destructive confirmation | Not applicable — no destructive actions in Phase 3 |

**Copy principles for this phase:**
- "Play" and "Stop" are intentional domain convention matching media player standards (transport controls) — not generic form labels. Musicians and general users share this mental model universally; no rewording to "Start"/"Pause" or similar.
- No Italian tempo labels (Andante, Allegro) — explicitly out of scope per REQUIREMENTS.md
- Labels are terse; musicians know what "BPM", "8th", "Triplet" mean
- Avoid redundant "notes" suffix (use "8th" not "8th notes")
